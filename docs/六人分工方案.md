# 中国象棋项目 · 六人分工方案

> 配套文档：`docs/接口契约.md`（函数签名与数据结构以此为准）
> 周期：3 周 / 15 个工作日　·　角色：架构集成 1 + 逻辑 2 + 前端 1 + 算法 1 + 质量 1

---

## 一、分工原则

1. **一人一目录，文件独占**。谁的文件谁改，别人要功能就提 issue，不许直接动手。
2. **按"依赖方向"切，不按"功能多少"切**。切断点必须落在**已经冻结的接口**上，这样两个人可以同时开工而不用等对方。
3. **每个工作包都能独立验收**，验收物是"一个能打开的 test.html + 里面全绿"，不是"我写完了"。
4. **最难的那块给最能扛的人，但把它拆成按天交付**（规则引擎按兵种交付，不做一个大黑盒）。

## 三、每人详细任务卡

### A · 你｜架构 & 集成（10 人日）

**你要做的三件事，按优先级：**

1. **定契约、铺骨架**（第 1 天，半天）
   - 目录结构 + 空文件 + `CC.Test` + 这份契约文档，一次性发到群里。
   - 这一天的产出决定了另外五个人能不能同时开工。
2. **P0 地基**（第 1–2 天，**硬约束**）
   - `board.js`：坐标、棋子编码、`clone`、`parseFEN/toFEN`。
   - 写一个 `test.html`，用起始 FEN 往返一次必须完全一致。
   - **这是全项目唯一的关键路径**，晚一天，五个人一起等。
3. **P7 总装**（第 2 周起）
   - 先用 `CC.AI.randomMove` + 假局面把"点击→走子→重绘"这条链路跑通（第 3 天就能跑）。
   - 再逐步替换成真规则、真 AI。**总装要早、要空**，不要等到最后一周才开始拼。

**你额外要守的：**
- 契约变更的唯一批准人。任何人要改签名，必须你点头 + 群里公告 + 24 小时缓冲期。
- 第 1 周结束主持一次 30 分钟"对表会"：每人用 5 分钟讲"我的函数被谁调用、我期望别人给我什么"，把理解偏差当场撞掉。
- 兜底：谁掉队，你顶他的模块（所以你的技术栈要跟所有人一致，不要自己另开一套）。

---

### B · 规则引擎（16 人日）· 全项目最关键的一块

**交付节奏：按兵种切，每天一个可验收的小块，不要憋大招。**

| 天 | 交付 | 验收 |
|---|---|---|
| D2 | 车、炮（含炮翻山吃子） | 车 4 向无阻挡；炮不吃子要隔一子、吃子必须隔且仅隔一子 |
| D3 | 马（蹩马腿）、象（塞象眼、不过河） | 8 个蹩腿位置逐个用例 |
| D4 | 士（九宫斜走）、将（九宫一步） | 九宫边界 4 角用例 |
| D5 | 兵/卒（过河前后差异） | 河界两侧横走用例 |
| D6 | `applyMove` / `undoMove`，halfMove/fullMove 维护 | 走→悔→局面完全还原（逐格比对） |
| D7 | 全兵种回归 + 性能（`movesFor` 单次 < 0.1ms） | fixtures 全绿 |

**必须注意：**
- `applyMove` **返回新状态、不改入参**（AI 和悔棋都靠这个）。
- 提供 `undoMove` 快通道给 E，**E 的搜索性能全靠它**，别只给不可变版本。
- 只写"符合走法"的伪合法着法，**不判断送将**——那是 C 的活。越界了就会和 C 打架。

**风险**：这是最容易延期的一块。如果 D5 还没全绿，立刻砍"兵过河特殊处理"以外的一切优化，先保正确性。

---

### C · 对局控制（14 人日）

**你的优势：前半段不依赖 B。** 第 1 周先写 `isAttacked`（只依赖 `board.js`），反向扫描格子，**不要**调用 `genPseudoMoves` 全集——否则 E 的搜索会慢一个数量级，他会来砍你。

| 阶段 | 交付 |
|---|---|
| W1 | `isAttacked`、`isKingsFacing`（将帅照面）、`validate` 骨架（先用 B 的桩） |
| W2 上半 | `legalMoves`（过滤送将）、`status`（将死/困毙/进行中） |
| W2 下半 | `game.js`：`play / undo / reset / legalTargets` + 四个事件 |
| W3 | 长将、60 回合自然限着、边界修复 |

**接口红线：**
- `CC.Game` 是**全项目唯一有状态的对象**，其他人只通过 `getState()` 和事件跟它打交道。
- 事件名只有四个：`move / undo / reset / end`，不许新增。
- `legalTargets(x, y)` 是 D 的高亮数据源，**第 2 周中必须稳定**，否则 D 卡住。

---

### D · 界面交互（12 人日）

**你从第 1 天就能开工，因为你可以拿假数据。**

| 阶段 | 交付 | 关键点 |
|---|---|---|
| W1 | 静态棋盘：9×10 线、九宫斜线、楚河汉界、32 子摆放 | 传入一份硬编码 state 就能画对 |
| W2 上半 | 点击选子 + 落子回调 `onCellClick(x, y)` | 只上报坐标，**不判断合法性** |
| W2 下半 | 高亮（可走点/上一步/被将）、拖拽走子 | 高亮数据从 `game.legalTargets` 取 |
| W3 | 走子动画、将军闪烁、翻转视角、移动端适配 | 动画结束必须回调，否则状态错乱 |

**红线：**
- 渲染**只读 state，永远不修改**。所有用户操作只通过回调上报坐标。
- 你是唯一碰 DOM 的人，其他人不许写一行 CSS。
- 早期拿不到 `legalTargets` 时，可以先用 `CC.Rules.movesFor` 显示（会显示非法点），标注 `// TODO` 后第 2 周切回来。

---

### E · AI 算法（13 人日）

**第 1 天就要交东西，不要一开始就写搜索。**

| 阶段 | 交付 | 意义 |
|---|---|---|
| D1 | `CC.AI.randomMove` | **让 A 的总装当天就能跑通**，这是全项目的"活体骨架" |
| D2–D4 | `evaluate`：子力价值 + 位置表（车马炮优先） | 单位统一 1 兵 = 100，红正黑负 |
| W2 | negamax + Alpha-Beta + 迭代加深 + 时间限制 | 3 秒内出着，深度至少 4 层 |
| W3 | 置换表、走法排序（吃子优先）、三档难度 | 简单/普通/困难差异明显 |

**性能约定：**
- 内部可以用可变棋盘做 make/unmake 快通道，但**对外只吃 `GameState`、只吐 `Move`**。
- 遇到性能墙先找 B 要 `undoMove`，不要自己另写一套棋盘复制。
- 3 秒拿不到结果就返回当前最优，**宁可浅一层也不能卡死界面**（必要时做 Web Worker，但要先跟 A 报备）。

---

### F · 棋谱 & 质量（7 人日）

**你是质量守门人，不是功能开发。**

1. **W1：先建 fixtures**（半天）
   - 20 个起步局面，覆盖：开局、将军、将死、困毙、照面、马蹩腿、炮翻山。
   - 格式统一 `{ name, fen, side, expect: [...] }`，所有人共用同一份。
   - 同时把 `CC.Test` 的四个断言（`eq/ok/moves/report`）接到每个模块的 `test.html` 里，做成模板，别人复制即用。
2. **W1–W2：中文记谱**
   - 路数换算是最容易错的：**红方路数 = `9 - x`，黑方 = `1 + x`**；红用汉字、黑用阿拉伯数字；同线双子用前/后。
   - 先写 `toChinese`，`fromChinese` 可以后置。
3. **W2：PGN 导出/导入 + `replay` 回放**。
4. **W3：回归**
   - 每两天跑一次全模块测试页，把通过数报到群里（**这是唯一客观的进度指标**）。
   - 发布前出一份 checklist：开一局、走三步、悔一步、重开、导出棋谱、导入回放。

## 五、协作机制

- **站会**：每天 10:30，10 分钟，每人只答三句——昨天交付了什么、今天交付什么、卡在哪。**不许讨论技术细节**，会后单聊。
- **分支**：`feat/<名字>-<模块>`，每天 rebase `main`；`main` 只在集成日合并，且必须 test 全绿。
- **评审**：跨模块 PR 需模块 owner 批准；`app.js` 和契约文档你有一票否决。
- **契约冻结**：W1 末冻结 v1.0。之后改动 = 你批准 + 群公告 + 24 小时缓冲（留出别人调整的时间）。
- **冲突处理**：接口打架时**不改代码，先改文档**，改完两边同时动。谁先改代码谁回滚。

## 六、进度安排（3 周）

| 周 | 主目标 | 各人在做什么 | 周末状态 |
|---|---|---|---|
| **W1** | 地基 + 骨架跑通 | A 地基→总装空壳；B 车炮马象士将兵；C isAttacked；D 静态棋盘；E 估值+假 AI；F fixtures | 能在屏幕上摆出棋盘，假 AI 能走棋，规则逻辑过半 |
| **W2** | 功能补全 | A 接真规则；B 收尾+性能；C 合法着法+对局控制；D 点击拖拽高亮；E 搜索；F 记谱+回放 | 两个人能真下完一局，AI 能应招 |
| **W3** | 集成 + 打磨 | A 集成、全员修 bug；E 调参、D 动画、F 回归、C 边界 | 可发布版本 |

**W3 的铁律**：只修 bug 和打磨，**不加功能**。想加的功能记进 v2 清单。

## 七、风险与备份

| 风险 | 概率 | 应对 |
|---|---|---|
| B 规则延期，全员阻塞 | 高 | 按兵种拆日交付；C/E 先用桩数据；W1 末必须全绿 |
| AI 太慢，卡界面 | 中 | 硬性时间限制 + 迭代加深；必要时 Web Worker（先报备） |
| 坐标/编码理解不一致 | 中 | 契约文档 + D1 对表会 + 每日 fixtures 回归 |
| D 等 C 的接口 | 中 | 先用 `movesFor` 顶着，允许短暂显示非法点 |
| 有人请假/掉队 | 低 | **B ↔ C 互为备份**（逻辑相通），A 兜底任意模块 |
| W3 发现大坑 | 中 | 砍需求不延期；保留"随机 AI"作为降级方案 |

## 八、作为带头的，你只需要盯这五件事

1. **D2 晚上 `board.js` 必须能用**——这是全项目唯一的硬约束，其他都能协商。
2. **每天看 fixtures 通过数**，不看"我写了 80%"。数字是唯一不会骗人的进度。
3. **守住"先改文档再改代码"**。你松一次口，接口就开始漂，最后一周会加倍还回来。
4. **W1 末的对表会不能省**。六个人对同一份文档的理解一定有偏差，早撞比晚撞便宜十倍。
5. **W2 末做减法**。发现做不完，砍功能、砍动画、砍难度档位，唯独不砍规则正确性和测试。
