# 中国象棋项目 · 接口契约 v1.0

> 用途：多人并行开发时的**唯一事实来源**。函数名、参数、返回值、数据结构以本文件为准。
> 规则：**先改文档，再改代码**。任何接口变更都必须提 PR 修改本文件并在群里同步，不允许口头约定。

对应拆分方案：P0 地基 → P1 渲染 → P2 规则 → P3 校验 → P4 对局 → P5 AI → P6 棋谱 → P7 总装。

---

## 一、全局约定（必须一致，任何人不得私自变更）

### 1.1 技术栈与文件形态
- 原生 HTML / CSS / JavaScript，**零依赖、零构建**。
- **不使用 ES Module**（`file://` 下会被 CORS 拦截），所有文件用经典 `<script>` 引入，挂到全局命名空间 `CC` 上。
- 引入顺序固定：`board.js → rules.js → validate.js → game.js → notation.js → ai.js → view.js → app.js`。

### 1.2 命名空间与文件归属

| 命名空间 | 文件 | 归属 | 职责 |
|---|---|---|---|
| `CC.Board` | `core/board.js` | P0 | 数据结构、坐标、FEN、克隆 |
| `CC.Rules` | `core/rules.js` | P2 | 走法生成、合法性、走子 |
| `CC.Check` | `core/validate.js` | P3 | 将军、照面、终局判定 |
| `CC.Game` | `core/game.js` | P4 | 对局控制器、回合、悔棋、事件 |
| `CC.Notation` | `core/notation.js` | P6 | 中文记谱、PGN、回放 |
| `CC.AI` | `ai/engine.js` | P5 | 估值、搜索、假 AI |
| `CC.View` | `ui/board-view.js` | P1 | 渲染、高亮、动画 |
| `CC.Test` | `test/test-kit.js` | 共用 | 断言工具（见第四节） |

**只写自己模块的文件。** 需要别人加功能 → 提 issue 改本契约，不要直接改别人文件。

### 1.3 坐标系统（最容易出错，务必按图）

```
        x=0  1  2  3  4  5  6  7  8
   y=0  ┌──┬──┬──┬──┬──┬──┬──┬──┐     ← 黑方底线
   y=1  ├──┼──┼──┼──┼──┼──┼──┼──┤
   ...  │  │  │  │  │  │  │  │  │
   y=4  ├──┼──┼──┼──┼──┼──┼──┼──┤     ← 楚河汉界
   ...  │  │  │  │  │  │  │  │  │
   y=9  └──┴──┴──┴──┴──┴──┴──┴──┘     ← 红方底线
```

- `x`：0–8，**从左到右**（以红方视角，即屏幕视角）。
- `y`：0–9，**从上到下**，`y=0` 是黑方底线，`y=9` 是红方底线。
- 一维下标统一：**`idx = y * 9 + x`**，`board` 长度恒为 90。
- 越界判断统一走 `CC.Board.inBoard(x, y)`，不要在各自模块里手写 `x >= 0 && x < 9`。

### 1.4 棋子编码（标准 X-FEN）

| 红（大写） | K 帅 | A 仕 | B 相 | N 马 | R 车 | C 炮 | P 兵 |
|---|---|---|---|---|---|---|---|
| 黑（小写） | k 将 | a 士 | b 象 | n 马 | r 车 | c 炮 | p 卒 |

- 空位统一用 **`null`**（不要用 `''`、`0`、`undefined` 混用）。
- 阵营判断只走 `CC.Board.sideOf(piece)`，返回 `'r' | 'b'`。
- **不要**用汉字或 `'red-rook'` 一类字符串，渲染层自己负责转汉字。

### 1.5 数据契约

**GameState（不可变，禁止原地修改）**
```js
{
  board: Array(90),   // board[y * 9 + x] → 'K'..'P' | 'k'..'p' | null
  turn: 'r' | 'b',    // 轮到谁走
  halfMove: 0,        // 距上次吃子的半回合数（60 回合自然限着用）
  fullMove: 1         // 回合数，红走完 +1
}
```

**Move（着法，轻量扁平结构）**
```js
{
  from: [x, y],           // 起点
  to:   [x, y],           // 终点
  piece: 'R',             // 动子（悔棋、回放、记谱都要用，必填）
  captured: 'p' | null    // 被吃子，无则为 null
}
```

**Result（统一返回值，所有"会失败"的函数都返回它）**
```js
{ ok: true,  move: Move, state: GameState, status: 'playing' }
{ ok: false, reason: 'E_ILLEGAL_MOVE' }
```
> 规则层**一律不抛异常**。异常只用于程序员错误（如传了长度不是 90 的数组）。

**Status（对局状态）**：`'playing' | 'r-win' | 'b-win' | 'draw'`

**错误码（枚举，禁止自定义字符串）**

| 错误码 | 含义 |
|---|---|
| `E_NOT_YOUR_TURN` | 不是该方走棋 |
| `E_EMPTY_CELL` | 起点没有棋子 |
| `E_OWN_PIECE` | 终点是自己人 |
| `E_OPPONENT_PIECE` | 动了对方的子 |
| `E_OUT_OF_BOARD` | 坐标越界 |
| `E_ILLEGAL_MOVE` | 不符合该兵种走子规则 |
| `E_SELF_CHECK` | 该着会导致己方被将 |
| `E_GAME_OVER` | 对局已结束 |

### 1.6 编码风格
- 2 空格缩进、单引号、语句结尾加分号、`const` 优先。
- 命名：函数 `camelCase`、常量 `UPPER_SNAKE`、文件 `kebab-case.js`。
- 动词前缀统一：`create` 造、`get` 取、`set` 设、`is/has` 返布尔、`gen` 生成列表、`apply` 产生新状态、`parse/to` 序列化、`on/emit` 事件。
- 布尔函数一律以 `is/has/can` 开头，不返回 `null`。

## 二、函数接口清单

### P0 `CC.Board` — 数据结构与坐标

| 函数 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `create` | — | `GameState` | 标准起始局面 |
| `empty` | — | `Array(90)` | 全 null 棋盘 |
| `idx` | `x, y` | `number` | `y*9+x` |
| `inBoard` | `x, y` | `boolean` | 是否在盘内 |
| `at` | `state, x, y` | `string \| null` | 取某格棋子 |
| `set` | `state, x, y, ch` | `GameState` | 放子，返回新状态 |
| `clone` | `state` | `GameState` | 深拷贝（board 逐格复制） |
| `sideOf` | `piece` | `'r' \| 'b' \| null` | 阵营 |
| `isRed` | `piece` | `boolean` | 是否红子 |
| `parseFEN` | `fen` | `GameState` | 解析（空位数字、`/` 分行、`w/b` 走子方） |
| `toFEN` | `state` | `string` | 反向序列化，与 parseFEN 互逆 |

起始 FEN（联调基准，所有人共用）：
```
rnbakabnr/9/1c5c1/p1p1p1p1p/9/9/P1P1P1P1P/1C5C1/9/RNBAKABNR w - - 0 1
```

### P2 `CC.Rules` — 走法生成（纯函数，不校验将军）

| 函数 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `genPseudoMoves` | `state, side` | `Move[]` | 该方所有"符合走法但可能送将"的着法 |
| `movesFor` | `state, x, y` | `Move[]` | 单个子的着法（UI 高亮用） |
| `isAttacked` | `state, x, y, bySide` | `boolean` | 某格是否被 bySide 攻击（照面判定依赖它） |
| `applyMove` | `state, move` | `GameState` | **返回新状态，不修改入参**；负责吃子、切换 turn、维护 halfMove/fullMove |
| `undoMove` | `state, move` | `GameState` | 走 applyMove 的逆运算（供悔棋用） |

> 兵种细节归属 P2 自己：蹩马腿、塞象眼、炮翻山吃子、兵过河横走、士象不出九宫/不过河、将帅九宫一步。

### P3 `CC.Check` — 合法性与终局

| 函数 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `isInCheck` | `state, side` | `boolean` | side 是否被将军 |
| `isKingsFacing` | `state` | `boolean` | 将帅照面（白脸将） |
| `legalMoves` | `state, side` | `Move[]` | 过滤掉送将与照面后的真·合法着法 → **P4 只用这个** |
| `validate` | `state, move` | `Result` | 完整校验，失败带错误码 |
| `status` | `state` | `Status` | 判定将死/困毙/进行中 |
| `isCheckmate` | `state, side` | `boolean` | 被将且无解 |
| `isStalemate` | `state, side` | `boolean` | 未被将但无着可走 |

> 性能要求：`isAttacked` 不许调用 `genPseudoMoves` 全集（否则 AI 搜索会慢一个量级），按格子反向扫描。

### P4 `CC.Game` — 对局控制器（唯一有状态的对象）

| 成员 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `CC.Game.create` | `opts?` | `game` | `opts: { mode: 'pvp'\|'pve'\|'eve', aiSide: 'b', onMove, onEnd }` |
| `game.play` | `from, to` | `Result` | 落子；内部走 validate → applyMove → status |
| `game.undo` | — | `Move \| null` | 悔一步，返回被撤销的着法 |
| `game.reset` | — | `void` | 重开，触发 `reset` |
| `game.getState` | — | `GameState` | 当前局面（只读，调用方不得改） |
| `game.legalTargets` | `x, y` | `[x,y][]` | 该子可走点（UI 高亮专用） |
| `game.isOver` | — | `boolean` | 是否终局 |
| `game.status` | — | `Status` | 当前对局状态 |
| `game.on` | `event, cb` | `void` | 订阅事件 |
| `game.off` | `event, cb` | `void` | 取消订阅 |

**事件名固定四个**：`move`（参数 `move, state`）、`undo`（`move`）、`reset`（无参）、`end`（`status`）。
UI 与 AI 只通过事件响应，**不许直接读取内部数组**。

**对局模式（v1.1 新增）**

| 字段 | 取值 | 说明 |
|---|---|---|
| `mode` | `'pvp'`（默认）\| `'pve'` \| `'eve'` | 双人同屏 / 人机 / 机机（F 的回归测试用） |
| `aiSide` | `'r' \| 'b'`，默认 `'b'` | AI 执子方，仅 `mode !== 'pvp'` 时生效 |

- **AI 对手不内置在 `CC.Game` 里**：`Game` 只认 `play(from, to)` 的调用者，不区分人机。
- 接线归属 **app.js（P7）**：订阅 `move` 事件 → 轮到 `aiSide` 时调 `ai.search(state)` → 用返回的 `Move` 调 `game.play(move.from, move.to)`。
- `game.play` 需自行忽略"非当前执子方的调用"（返回 `E_NOT_YOUR_TURN`），这是防止 AI 与玩家双输入冲突的唯一闸门。

### P5 `CC.AI` — 引擎

| 函数 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `CC.AI.create` | `opts` | `ai` | `opts: { depth=3, timeLimit=3000, seed=null }` |
| `ai.search` | `state` | `{ move, score, nodes, timeMs }` | 同步返回最佳着法；无着可走时 `move = null` |
| `CC.AI.evaluate` | `state, side` | `number` | 局面估值，**以 side 视角，正数=己方优**。单位：1 兵 = 100 |
| `CC.AI.randomMove` | `state` | `Move \| null` | 假 AI，P7 先联调用 |

> 约定：AI 内部允许用可变棋盘做 make/unmake 快通道，但**对外只吃 `GameState`、只吐 `Move`**，不允许把内部结构漏到接口上。

### P6 `CC.Notation` — 棋谱

| 函数 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `toChinese` | `state, move` | `string` | 如 `炮二平五`、`马8进7` |
| `fromChinese` | `state, text` | `Move \| null` | 反向解析（可后置） |
| `toPGN` | `moves, meta?` | `string` | 导出棋谱 |
| `parsePGN` | `text` | `{ moves, meta }` | 导入 |
| `replay` | `state, moves, upto` | `GameState` | 快进到第 upto 步（回放用） |

**记谱路数换算（经典踩坑点）**：
- 红方路数 = `9 - x`（红方从自己右边数，一路在屏幕右侧）；
- 黑方路数 = `1 + x`；
- 红方用汉字数字（一二三…九），黑方用阿拉伯数字（1–9）；
- 同线双子用 `前/后` 区分，兵卒三子以上用 `前中后`。

### P1 `CC.View` — 渲染（唯一碰 DOM 的模块）

| 函数 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `CC.View.mount` | `el, opts` | `view` | `opts: { onCellClick(x,y), onDrop(from,to), flipped=false }` |
| `view.render` | `state` | `void` | 全量重绘 |
| `view.highlight` | `cells, type` | `void` | `type: 'move' \| 'lastMove' \| 'check' \| 'select'` |
| `view.animateMove` | `move, cb` | `void` | 走子动画，结束后回调 |
| `view.setFlipped` | `boolean` | `void` | 翻转视角 |
| `view.flashCheck` | `side` | `void` | 将军提示 |

> 渲染只读 `state`，**永远不修改 state**；用户操作只通过 `onCellClick` 上报坐标，由 P4 决定合法性。

## 三、模块依赖图（编译顺序即依赖顺序）

```
P0 Board  ──┬─→ P1 View ─────────────────┐
            ├─→ P2 Rules ─→ P3 Check ─┬─→ P4 Game ─┬─→ P7 App
            │                          │            ├─→ P6 Notation
            │                          └─→ P5 AI ───┘
            └────────────────────────────────────────┘
```
**禁止反向依赖**：Rules 不能调 View，View 不能调 Game，AI 不能调 DOM。

## 四、共享测试基建 `CC.Test`

所有模块的 `test.html` 用同一套断言，禁止各写各的 console.log。

| 函数 | 参数 | 说明 |
|---|---|---|
| `CC.Test.eq` | `actual, expected, label` | 相等断言，打印 ✅/❌ |
| `CC.Test.ok` | `cond, label` | 真值断言 |
| `CC.Test.moves` | `actual, expected, label` | 着法集合比对（**忽略顺序**） |
| `CC.Test.report` | — | 输出汇总：通过 / 失败数 |

共享测试局面放 `test/fixtures/*.json`，格式：`{ name, fen, side, expect: [...] }`。**同一份 fixture 所有人共用**，规则改坏了立刻能被别人的测试发现。

## 五、协作流程约定

1. **分支**：`main` 受保护，只接受 PR。每人一条长期分支（fwc/hsy/hyp/tmh/ycq/zzn），**合并权集中在 A**：队友只推分支、发 PR，评审与合并统一由 A 操作。
2. **提交信息**：`feat(p2): 支持马蹩腿判定`，模块号必填。
3. **接口变更**：先在 PR 里改 `docs/接口契约.md`，评审通过后合并，再改代码。**代码先于文档改动视为 bug。**
4. **每日联调**：各模块 `test.html` 全绿才能合并；总装分支每天跑一次 P7 冒烟（开一局、走三步、悔一步、重开）。
5. **不合并的情况**：接口签名偏离本文件、出现新的错误码字符串、跨模块直接改别人文件。
6. **命名统一清单**（自查）：`state`（不写 `game`/`boardState`）、`move`（不写 `step`/`chess`）、`side`（不写 `color`/`player`）、`x,y`（不写 `row,col`）。
   > 特别注意：全项目用 `(x, y)`，**不要混入 `row/col`**，这是坐标事故的第一来源。

## 六、完成定义（DoD）

一个小项目算完成，需同时满足：
- [ ] 对外函数与本文档签名一致；
- [ ] `test.html` 覆盖核心分支且全绿；
- [ ] 不依赖其他模块正在开发的未完成代码（可用 fixture 桩数据自测）；
- [ ] 无 `console.log` 残留、无 TODO 注释进 `main`。
